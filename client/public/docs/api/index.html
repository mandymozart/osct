API

Which API for what

Three ways to make an experience do more than show things. They share one runtime, so they work together.

You want toUseWhere
React to a find or a tap, remember something, show or hide a node, go to a sceneRulesThe Inspector, or the Logic panel. No code.
Move or animate over time, draw, compute, write a shader, add a new kind of nodeA pluginThe Code tab. TypeScript.
Have an AI agent build or change content for youThe MCP serverYour agent, connected with a token.

How they fit together

  • One event bus and one set of variables. A rule's emit is heard by a plugin's api.events.on; a plugin's api.vars.set is read by a rule's when.
  • Rules decide, plugins do. A rule says when the door is found and the reader has the key, emit openDoor. A plugin hears openDoor and swings the door over a second.
  • Reach for a rule first. Write a plugin when a rule would need a verb it does not have.
  • An agent edits the same content through the same API as the editor: entities, rules as components, plugin sources. It saves drafts; you publish.

The content underneath

All three write the same content model: an experience → scenes → surfaces, entries and targets → an entity's node tree with components. An agent can read the full model with the tool describe_content_model. For developers, the model and the HTTP API are documented in the repository: docs/content.md and docs/server.md.

Versions

These pages describe plugin API 3.1 and content schema 5.2. An older reader app skips what it does not know (a new component, a new parameter) with a quiet update hint; it never breaks.
