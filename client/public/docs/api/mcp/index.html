API

MCP server

The MCP server lets an AI agent work on an experience the way the editor does: read scenes, place content, write texts, rules and plugins. It acts as you, saves drafts, and gives you a link to check each change.

The two rules

  • The API decides. The agent has exactly your rights, minus what an AI connection is never allowed (below).
  • Readers are reached only by a person. The agent changes the draft. Publishing is your button in the editor.

Connecting

The easy way is in the editor: Experiences → Connect an AI agent makes a token and a prompt the agent sets itself up with. By hand, any MCP client that starts a stdio server needs four things:

WhatValue
Nameosct-<environment>: osct-staging, osct-production
Commandnode <path>/osct-mcp.mjs – one file, downloaded from this site at /mcp/osct-mcp.mjs. Needs Node 22.
OSCT_API_URLThis site's API, e.g. https://osct.porschuetz.de/api
OSCT_EDITOR_TOKENAn AI connection's token, osct_…
claude mcp add osct-staging --scope user \
    -e OSCT_API_URL=https://osct.porschuetz.de/api \
    -e OSCT_EDITOR_TOKEN=osct_… \
    -- node /path/to/osct-mcp.mjs

Claude Desktop, Codex CLI, OpenCode and Cursor take the same four values in their own config files; the editor's Set it up by hand shows each snippet filled in. Download the file again after the site was updated.

What a token may do

AllowedRefused (not-for-ai)
Everything an editor does to a draft: scenes, targets, entities, entries, files, plugins, reverts.Publishing, in any environment. Making or changing tokens. The password. Any change of the account: consent, language, deletion.

Every save by an agent is named in the change log with its token's name. A token expires after 182 days unless renewed, and stops at once when revoked.

First calls

  1. whoami – who the agent is signed in as, and with which token.
  2. list_experiences – what is here and where it is live.
  3. describe_content_model { experience } – node types, components, parameters, the experience's plugins. Read it before writing an entity.

Rules are part of an entity (a node's behaviour component) and written with put_entity or put_target. Before an entity is sent it is checked against the content model: a wrong type or a value out of range comes back with its path and never reaches the API.

Two steps before anything is lost

Tools that replace or remove things do nothing on the first call. They answer with what would happen and a confirmation; the agent must show you that and call again only with your yes.

ToolFirst call answersSecond call
import_experience, import_deliverythe comparison with the draftconfirm: <id>
delete_entry, delete_scenethe impact: what goes with itconfirm: <id>
move_scenes, group_scenes, revert_change, revert_tothe planapply: true
put_scene, put_surface (a surface in use)the entries and targets on itapply: true

If the draft changed in between, the confirmation is void and a new comparison comes back.

Seeing a scene

render_scene { experience, scene, view? } returns a picture of the scene as the editor's stage shows it, so the agent can check its own placement. Views: reader (default), top, low, far. It needs Chrome or Edge on the computer the agent runs on. It shows the stage; it cannot tap or scrub.

An example

“Add a target on the double page 30–31 with a tinted video.”

  1. get_experience finds the scene labelled 30–31; get_scene its surface and targets.
  2. describe_content_model: a video lies flat; rotation: [90, 0, 0] stands it up; the plugin tint exists.
  3. upload_asset twice: the video, and the printed image with fit: "target".
  4. add_entry with the title, the scene, and a target: its image, its place in mm, and the entity (a video node with a tint component).
  5. render_scene { view: "top" } to look; put_target to adjust.
  6. You open the link, check the stage, and publish.

Limits

  • The reader app's onboarding screens are not content: no tool edits them.
  • upload_asset takes a file on the computer the agent runs on.
  • Removing an experience's printed book stays your decision.

For developers, every tool with its parameters is in docs/mcp.md in the repository.
