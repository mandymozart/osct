API

The logic system

A rule says: on an event, when a condition holds, do these actions. Rules need no code. They are made in the Inspector or the Logic panel and stored in the content.

A rule

- on: found                    # the event: this node's page is found
    when: hasKey                 # optional: a condition
    do:                          # one action or a list, run in order
      - hide: hint
      - emit: openDoor

The demo's door: when its page is found and the reader has the key, hide the hint and send openDoor.

This is the content's form (YAML). In the editor you never write it: the Inspector's rule rows produce exactly this.

Events do not cross scenes. Only the open scene's nodes and rules exist. Carry state across scenes in a variable, or hear the event in an experience rule or a plugin, which live for the whole session.

Naming a node

  • In a node's rule: by the node's name (the Inspector's name row), among the nodes below the rule's node. An empty name means the rule's own node.
  • In a scene's or the experience's rule: by address. target:door is the root of the target door's entity; target:door/hint is the node named hint in it.
  • A scene: scene:epilogue.

Variables

ScopeLives
sceneWhile the scene is open. Cleared when it changes. The default.
stageWhile the AR view exists: across scene switches.
sessionUntil the app is closed.
experienceKept with the reader's progress.
  • Reading takes the innermost scope that has the name: scene, then stage, session, experience.
  • Types: number, integer, boolean, string. Declare a variable in the experience's Inspector (name, type, scope, default), or let its first set decide.
  • A declared variable that is not set reads as its default. An undeclared one that is not set is false in a condition.
  • Setting a value of another type is refused, in the editor and at runtime.

Expressions

A when and every set value is one expression.

PartExamples
Values3, 1.5, "calm", true, false, a variable's name
Logic&& || ! (also and or not)
Compare== != < <= > >=
Arithmetic+ - * / mod, parentheses
when: hasKey && tries > 2
  when: mood == "calm" || !doorOpen
  set:  { tries: "tries + 1" }      # a counter
  set:  { mood: '"calm"' }          # a text needs its quotes
  • A condition must be true / false: when: tries is a problem, when: tries > 0 is not.
  • + adds numbers or joins texts, never a text and a number. Nothing is converted but whole number → number.
  • No functions, no dotted names.

The same language works in an entry's text, in braces: {tries > 2: Try the window.}

How rules run

  • On one event, every rule's condition is read first; then the rules that matched run in order. So two rules can toggle a variable without undoing each other.
  • An emit sets off the rules that hear it at once. A chain deeper than 8 events is cut.
  • An action that cannot run (a node or clip that is not there) is logged, and the next one runs.

Rules and plugins

Rules run on the same runtime as plugin code:

A rule'sis a plugin's
on: doorOpenedapi.events.on("doorOpened", …)
emit: openDoorapi.events.emit("openDoor", { targetId, node })
set: { hasKey: true }api.vars.set("hasKey", true)
when: hasKeyapi.vars.get("hasKey")

So a rule can set off code and code can set off rules, by name. See events and variables in the Plugin API.

Testing

Select the scene and open vars and events: tap a target, change a variable, and read the timeline. Every rule that ran has a behaviour line with what it did. The Logic panel lists problems such as an event nothing emits.
