Editor guide

Experiences, import, publish

The start page lists the experiences here and is where one comes in. Publishing happens from inside an experience.

The Experiences page

Click a cover to open the experience. Under each one a line says where it is live and since when, or draft only.

Importing an experience

An import turns an experience's game configuration into a draft here. Three sources:

  • the CDN: the version this installation has published.
  • URL: a game.config.json, or a content base – an experience's folder on the CDN that holds latest.json, e.g. …/osct/staging/demo.
  • file: a game.config.json from your computer.

Assets at is where the media paths resolve. No media is copied: the draft points at the files where they are.

Before anything is imported the form shows what comes in: the build, its date, the app and schema version, the experience and what it holds.

The experience's id comes from the configuration. If a draft with that id exists, the import replaces it, so the editor shows a comparison first and imports only when you confirm.

Publishing

Publish is the cloud button in the top bar of an open experience. Next to it: draft only or live on ….

It opens a step that names the experience, the target and what it replaces there. Its button publishes; Cancel or Esc closes it.

  • An installation publishes to its own environment only: a local machine to local, staging to staging, production to production. There is no choice.
  • Each experience has its own store. Publishing one never touches another.
  • No CDN connected means this server stores and serves the published content itself.
  • Publish carries the draft and every saved plugin source. Unsaved code stays behind.

Going back: revert the draft in History, then publish again.

Readers open the installation's default experience at / and any other at /x/<experience>/.

AI connections

An AI agent (Claude Code, Claude Desktop, Codex CLI, OpenCode, Cursor) can work in the editor as you. It saves drafts and never publishes.

  • Connect an AI agent: pick the agent, press Create token & copy prompt, paste the prompt into the agent. It sets itself up.
  • Existing connections: each token with when it was last used and when it expires. Renew gives it another 182 days; Revoke stops it at once.

A token is shown once, so every agent gets its own. Details: MCP server.
