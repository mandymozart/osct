Editor guide

The Code tab

The Code tab holds the experience's plugins: TypeScript that adds components, node types, materials, passes and looks. A plugin can be one file or a few – each is a tab. You try code on the stage with Run and keep it with Save.

What a plugin can do is in the Plugin API; this page is about the tab.

The tab

  • Plugin: pick one of the experience's plugins. new starts one with two examples. An asterisk marks unsaved edits (spin*).
  • The files: one tab each, index.ts first. See The plugin's files.
  • The editor knows the plugin API: completion (Ctrl+Space), documentation on hover, type errors underlined – also across the plugin's files.
  • On the stage: the line under the editor says what of this plugin runs there (the saved version, edits not saved, failed, not loaded), how many files it has and how big its last bundle was.
  • Run (Ctrl+Enter): tries the files on the stage, saved or not.
  • Save (Ctrl+S): stores the files and runs them.
  • Download: the plugin as a zip with its types, to work on in your own editor – or to drop into another experience.
  • Delete: the whole plugin; refused while the draft uses something it registers.

The plugin's files

A plugin is a folder of files. index.ts is its entry: it exports register(api) and keeps its name. Next to it can be more TypeScript files and shaders (.frag, .vert, .glsl, .wgsl).

  • + at the right of the tabs adds a file – a TypeScript file, a fragment or vertex shader, a GLSL include, WGSL – or uploads files from your computer. Files dropped on the tabs join the plugin.
  • Rename a file with a double-click on its tab, F2, or its menu (right click).
  • The close cross deletes the file right away, as a change of its own. Undo in the top bar brings it back (so does History). Your unsaved edits in the other files stay as they are.
  • In index.ts, bring in a file by its name: import { wave } from "./wave" for TypeScript, import WATER from "./water.frag" for a shader – you get its text.
  • A plugin's zip (from Download) dropped on the tabs or into the Library becomes a new plugin.

Every save, push or delete of a plugin is in History and can be reverted there or with Undo – a deleted plugin comes back with all its files.

What Run does

  1. The plugin's files are put together into one module in your browser (a plugin of several files loads a small bundler the first time). Types are removed, not checked.
  2. The stage loads it and registers what it adds, replacing the previous Run.
  3. The scene is built again. A new component now shows under add component in the Inspector, a pass under add pass, a node type under + node.

Errors show under the editor and on their line – in another file, its tab comes forward. What ran before stays registered. The log below has the plugin's api.log lines and its errors on the stage.

Saved sources load by themselves

Every time the workspace opens, the saved plugins are loaded onto the stage. Run is only for trying edits before you save them.

If a plugin hangs the stage, the editor skips it on the next open and says so. Fix it, then Run it by hand.

Reaching readers

  • A Run reaches no reader. Publish does: it carries every saved plugin.
  • Unsaved edits stay behind.
  • Publish checks the types of every file first: a type error stops it and names the plugin, the file and the line.
  • A plugin that does not build stops the publish too, and so does a node that uses a component, node type, material, pass or look no plugin provides.
  • A plugin above 256 KB (bundled) is a warning in the publish, not a stop – readers download it with the AR scene.

Developing in your own folder

A plugin can live in a folder on your computer, where your own editor and tools work on it. The osct command links the folder to a plugin of the experience: osct plugin link once, then osct plugin push sends the folder's files (it checks the types first; --watch sends every change). The stage runs them at once, and the Code tab shows a line linked · … folder, pushed …. Edits made in the Code tab are allowed – osct plugin pull brings them back to the folder. Unlink ends the link; the files stay. How to set it up: Plugin API · your own folder.

Where the code runs

In the editor, plugins run in the editor's page, with your session: a plugin can do what you may do here – read and change the draft, the data, the game state. So before the stage runs plugin code that someone else saved last, the editor asks: Run plugin code by …?, with each plugin and who saved it. Run runs them; Don't run leaves them off the stage, and the Code tab and the Log tab say why. The answer is kept in this browser until someone else saves a new version. Your own code runs without asking. In the reader app the published plugins run in the app's page.
