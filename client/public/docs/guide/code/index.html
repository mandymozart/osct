Editor guide

The Code tab

The Code tab holds the experience's plugins: TypeScript that adds components, node types, materials, passes and looks. You try code on the stage with Run and keep it with Save.

What a plugin can do is in the Plugin API; this page is about the tab.

The tab

  • Plugin: pick one of the experience's plugins. new starts one with two examples. An asterisk marks unsaved edits (spin*).
  • The editor knows the plugin API: completion (Ctrl+Space), documentation on hover, type errors underlined.
  • On the stage: the line under the editor says what of this plugin runs there: the saved version, edits not saved, failed, or not loaded.
  • Run (Ctrl+Enter): tries the text on the stage, saved or not.
  • Save (Ctrl+S): stores the source and runs it.
  • Download: the plugin as a zip with its types, to work on in your own editor.
  • Delete: refused while the draft uses something the plugin registers.

What Run does

  1. The TypeScript is turned into JavaScript in your browser. Types are removed, not checked.
  2. The stage loads it and registers what it adds, replacing the previous Run.
  3. The scene is built again. A new component now shows under add component in the Inspector, a pass under add pass, a node type under + node.

Errors show under the editor and on their line. What ran before stays registered. The log below has the plugin's api.log lines and its errors on the stage.

Saved sources load by themselves

Every time the workspace opens, the saved plugins are loaded onto the stage. Run is only for trying edits before you save them.

If a plugin hangs the stage, the editor skips it on the next open and says so. Fix it, then Run it by hand.

Reaching readers

  • A Run reaches no reader. Publish does: it carries every saved source.
  • Unsaved edits stay behind.
  • A source that does not compile stops the publish and names the line.
  • Type errors are not checked at publish. Fix what the editor underlines first.
  • A node that uses a component, node type, material, pass or look that no plugin provides stops the publish too.

Where the code runs

In the editor, plugins run in the editor's page, with your session: a plugin can do what you may do here – read and change the draft, the data, the game state. So before the stage runs plugin code that someone else saved last, the editor asks: Run plugin code by …?, with each plugin and who saved it. Run runs them; Don't run leaves them off the stage, and the Code tab and the Log tab say why. The answer is kept in this browser until someone else saves a new version. Your own code runs without asking. In the reader app the published plugins run in the app's page.
