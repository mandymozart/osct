Editor guide

Library and Environment

The Library holds every file of the experience: uploads and the files an import brought. The Environment tab sets the sky around the reader.

The Library

  • Scope: This scene (files the open scene uses), All, Unused.
  • Search by name, entry or scene. Upload, or drop files on the panel.
  • Kinds: Targets, Surfaces, Images, Video, 3D, Audio, Code, Nodes.
  • Sort, tile size, tiles or list. ⋯ has more: where files come from, and Name by use….
  • ⤢ opens the Library as a large browser over the stage, with places on the left and multi-select.

A tile shows a preview, the kind (top left) and how often the file is used (top right; a dashed 0 = unused).

Ctrl+L jumps to the Library and focuses its search; again, back to the Inspector.

Using a file

ToDo

Pick for one fieldLibrary… next to any file field opens the Library as a picker with only the files that fit.

DeleteRefused while the file is used; Delete anyway forces it. Imported files are read-only.

Select a tile to open its details at the bottom: preview, size, where it is used (click to go there), the credits line and every action.

A drop that does not fit is refused and says why, e.g. A model node takes a 3D model – not a picture.

What happens on upload

  • Pictures become WebP in the browser, upright and scaled down: at most 1200 px for a target's printed image, 2048 px otherwise. The notice line says what became of the file.
  • Videos and sounds are stored as they are. Make their quality levels beforehand.
  • A .ts or .js file becomes a plugin in the Code tab, a plugin's zip (its Download) a plugin with all its files. A shader (.glsl, .frag, .vert, .wgsl) becomes a file plugins load by its URL – a shader only one plugin uses can be a file of that plugin instead (the Code tab).
  • Subtitles: speak.en.vtt belongs to speak.mp4 by its name.

Files that belong together stand together: a model's texture in several sizes is one stacked tile, a video and its subtitles one frame.

Name by use… renames files after where they are used (p118-1_target.webp). It shows the plan first. URLs never change.

The Environment tab

What a reader sees around the experience when they look up from the page.

  • Sky: an equirectangular image (2:1), or none. Library… picks one, Upload… adds one.
  • Onion sky: looking up, sky-like parts of the camera picture show the sky. It needs a camera picture, so only the reader shows it.
  • Preview · look up: raises the stage's camera towards the horizon and the sky. Not saved.

Once an experience has a sky, the stage shows it in every tab, in place of the studio. Use the default removes it.
