Plugin development with an agent

Develop and fine-tune an animation or an effect on your own computer with an AI agent – Claude Code, Codex, Cursor, any agent that edits files and runs commands. There is nothing to download but your plugin: the agent builds the small preview it needs, and the editor's stage is where it is judged.

1 · Connect the agent

  1. In the editor's experiences page, open AI connections and Connect an AI agent. It shows the setup for your agent (MCP server).

  2. Start the agent and ask it to read osct://guides/plugins – the full plugin guide, served by the MCP server. It knows the API from there.

2 · Make a folder

  1. In the editor's Code tab, press new for a new plugin (or pick one), then Download. Unpack the zip into an empty folder: the plugin's files, plugin-api.d.ts, shader-files.d.ts and tsconfig.json.

  2. With a checkout of the repository you can instead run osct plugin link <experience> ./<folder> – it writes the same files (Your own folder).

  3. In the folder: npm install --save-dev typescript @types/three@0.174 three@0.174 – the reader's three.js. npx tsc --noEmit then checks the plugin as the editor's Publish does.

3 · Give the folder its rules

Save this as AGENTS.md in the folder (and a CLAUDE.md that says read AGENTS.md). The agent reads it at every start.

# An OSCT plugin

- The plugin is `index.ts` (it exports `register(api)`) and the `.ts` / `.frag` / `.vert` / `.glsl` / `.wgsl` files next
  to it. The guide is osct://guides/plugins (the MCP server) – read it before writing code.
- Import nothing but the plugin's own files (`./name`) and `import type`. three.js is `api.three` (or the context's
  `three`), never `import "three"` – the build refuses a second three.js.
- Type names in camelCase. Every parameter the author should tune goes into the spec, with `min`, `max`, a `default`, a
  `description` and a short `label` – the editor builds its controls from it.
- It runs on a phone: few draw calls, no allocation per frame, a feedback buffer at 256² first, at most 256 KB bundled.
  Dispose what you create in `dispose`.
- A layer's GLSL works in linear RGB; a ShaderMaterial ends with `#include <colorspace_fragment>`.
- Borrowed code (Shadertoy, GitHub) keeps its author, link and licence at the top of its file.
- `harness/` is my preview only – throwaway, never part of the plugin. The editor's stage decides how it looks.
- `npx tsc --noEmit` before every hand-off. Save to the experience with put_plugin only when I ask; never publish.

4 · Let it ask first

Tell the agent what you have in mind and let it ask. These questions decide what the plugin is:

QuestionWhat it decides
What should change: how something looks, what it does, what it is, the whole picture, how it appears or disappears, the card's pick-up?A layer or material · a component · a node type · a pass · a look · a card look (what a plugin can register)
On what – a video, an image, a model, text, something new? Which experience and scene?Which nodes it fits
How should it feel? Timing, references, what happens when the page is found, lost, tapped?The hooks and the timing
What should you tune in the editor, and within which range?The spec – the rows of the Inspector
Does it react to the story – a rule, another node, a variable?Events and variables, or a rule and no code
Which files: a model, a picture, a shader, borrowed code?Library parameters, the plugin's files, the credit

Ask it to show the spec first. The parameters are what you will tune, so agree on them before the code.

5 · Tune it in a preview of its own

  1. Ask the agent for a preview page in harness/: a page in the place of the book, your plugin on it, sliders made from the spec, and a reload in a second.

  2. Ask for the reader's conditions: a transparent picture, linear colour, the page one unit wide, a 60° camera, a little hand-held wobble. The repository's sandbox/reveal/ shows how the engine's own sandboxes do it.

  3. Tune. When you like a value, have the agent write it into the spec's default.

The preview only comes close: the engine's lights, glow, placement and the camera picture are the reader's. Judge it on the editor's stage.

6 · Hand it over and look at it on the stage

  1. Ask the agent to save it to the experience (put_plugin, or osct plugin push --watch). It is a saved change of the draft, in History like a save in the Code tab.

  2. Have it placed on a node to try, and open the link the agent gives you. The Inspector shows your parameters as rows; tune them on the stage.

  3. Readers get it with the editor's Publish – your button, never the agent's.
