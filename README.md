# OSCT – Onion Skin & Crocodile Tears

Web AR companion app for Kévin Bray's book *Onion Skin & Crocodile Tears* (buildingfictions).
Readers scan the book's pages with their phone: found images unlock entries (glossary, videos,
texts, links) that can be read later in consultation mode. Runs in the browser, no tracking.

Staging: https://osct.netlify.app (built from `main`)

## Repository

| Folder | What |
|---|---|
| `client/` | The app (Vite, A-Frame + MindAR, vanilla web components, Immer store) |
| `content/` | Book content as YAML + media – the only place authors edit |
| `scripts/` | Content build: `content/` → `client/src/game.config.json` + `client/public/assets/content` |
| `shared/` | Game configuration contract (types + runtime guards), used by `client/` and `scripts/` |
| `mind-ar/` | Generated by the content build: target images per spread, in MindAR order, for compiling `.mind` files |
| `docs/` | Documentation site (Docusaurus) |
| `agents/` | Plan, rules, decisions and the design reference (start here when working on the code) |

## Quick start

Node 22 (as in CI).

```bash
# once
cd scripts && npm install && npm run build      # compile the content build tool
cd ../client && npm install

# after changing content/ (or shared/, scripts/src)
cd scripts && npm run build:content             # add --force: npm run build:content:force

# app
cd client && npm run dev                        # http://localhost:5173
```

- The content build only runs when its inputs changed (content, `shared/`, `scripts/src`, version).
  Commit the regenerated `client/src/game.config.json` and `client/public/assets/content` –
  CI fails if they are out of date.
- The camera needs HTTPS or `localhost`. To test on a phone, use the Netlify deploy or an HTTPS
  tunnel to the dev server.
- `client/.env` sets `VITE_DEBUG=true` (debug overlay with version, AR strategy and QR generator).

## Checks

```bash
cd client && npx tsc --noEmit && npx vitest run
cd scripts && npm run build                     # type-check + bundle the content build
```

CI (`.github/workflows/ci.yml`) runs these on every push and checks that the committed
game configuration matches `content/`.

## Build

```bash
cd client && npm run build                      # → client/dist (static SPA)
npm run build:ar-rebuild                        # same, AR strategy "rebuild" (one scene per spread)
npm run build:ar-persistent                     # same, AR strategy "persistent" (one scene, swaps targets)
```

`npm run build` uses the default strategy ("rebuild") or `VITE_AR_STRATEGY`; the debug overlay
shows the active one. In dev builds, `localStorage["osct-ar-strategy"]` overrides it (reload
after changing).

Netlify builds `main`; the FTP production deploy follows later.

## Version

One semver for app and content build: `client/package.json` and `scripts/package.json` always
carry the same version (checked by tests and CI). After a version bump, rebuild the content.
