## What the camera reported

The engine asks for "the back camera". On the S22 the browser has two back lenses:

| | camera 0, facing back | camera 2, facing back |
|---|---|---|
| Lens | main (4080 × 3060) | ultra-wide (4032 × 3024) |
| Focus modes | manual, single-shot, continuous | **manual only (fixed focus)** |
| Focus range | 0.10–8.1 m | – |
| Zoom | 1–10× | 1–8× |
| Tap to focus (`pointsOfInterest`) | no | no |
| Opened at | 960 × 720 (720 × 960 portrait), 30 fps | 960 × 720, 60 fps |

**The first test ran on camera 2, the ultra-wide lens.** It cannot focus at all, and its wide field of view makes a
small trigger even smaller in the picture – both match what Tilman saw ("the camera does not focus").

Why: on Samsung (and on any Android browser with the reduced user agent, which names no maker) the engine looks for
the label `camera2 0, facing back`. Chromium now labels the lenses `camera 0, facing back` – Chrome 156 and Brave 155
alike – so the engine finds nothing and asks for `facingMode: environment`; the browser then opens camera 2.

Fix (#37): the app changes the engine's camera request on the way and asks for camera 0 by its device id
(`ar-bridges/utils/camera-request.ts`). Checked on the phone: the engine then runs on camera 0 with continuous focus.

The focus distance stays at 0.00 in the readout while focusing continuously – Chrome does not report the distance the
autofocus settles on.

## iPhone 7 (Safari)

iPhone 7, iOS 15.8.3 (the last iOS for this phone), Safari 15.6. **Image tracking cannot run on it.**

- The dev server first did not start the app at all: its TypeScript transform turned static class fields into
  `static {}` blocks, which Safari before 16.4 cannot parse. The dev server now lowers them for Safari 15 (as the
  build does) – `vite.config.js`.
- The app then started, but AR failed: `WebAssembly.Module doesn't parse … can't get Function local's type …, in
  function at index 161`. The engine's tracking WebAssembly (`xr-tracking.js`) uses **WebAssembly SIMD** (`v128`
  locals in 423 places, the first in function 161), and the engine ships no build without it. Safari supports
  WebAssembly SIMD from iOS 16.4; the iPhone 7 (and 6s, SE 1st generation) cannot update that far.
- What Safari 15 reports for the camera (diagnostic page, the camera without the engine):

| | |
|---|---|
| Cameras | Front Camera, Back Camera (one back camera) |
| Picture | 720 × 960 @ 30 fps (up to 4032 × 3024, 60 fps) |
| Focus mode, focus distance, zoom, tap to focus | none – Safari 15 reports no camera controls; the phone focuses by itself |
| WebAssembly SIMD | false |

Open (Tilman): a "device not supported" notice below iOS 16.4 instead of the generic AR error, and whether a
SIMD-free engine build for older iPhones is possible and fast enough.
