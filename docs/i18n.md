# Languages (i18n)

UI texts use [i18next](https://www.i18next.com/) with the
[browser language detector](https://github.com/i18next/i18next-browser-languageDetector) and are
maintained with [i18next-cli](https://github.com/i18next/i18next-cli). Languages: English (default),
French, Dutch, German – informal everywhere ("tu", "je", "du").

```
client/
├── i18next.config.ts          i18next-cli: locales, where keys are extracted from, JSON + types output
└── src/i18n/
    ├── index.ts               i18next setup (JSON resources, fallback, detector) – imported first in main.ts
    ├── languages.ts           language list and names
    ├── i18next.d.ts           typed keys (created once by `i18next-cli types`, may be edited)
    ├── resources.d.ts         generated from the English JSON by `i18next-cli types` – don't edit
    └── locales/
        ├── en/                English – the reference, one JSON file per namespace (page or area):
        │   about  camera  common  entries  entry  header  home  notFound  progress  scan  settings  startup  tutorial
        ├── fr/  nl/  de/      the same files
```

The files are [i18next JSON v4](https://www.i18next.com/misc/json-format): nested keys, `{{placeholders}}`.
Lists are objects with numbered keys (`"0"`, `"1"`, …) – i18next-cli keeps them that way.

## In code

```typescript
import i18next from "i18next";

i18next.t("entry:accessPage");                            // "Access page"
i18next.t("entry:goToPage", { page: 4 });                 // {{page}}; values are escaped for HTML
Object.values(i18next.t("camera:chromeSteps", { returnObjects: true })); // lists
```

Keys (`namespace:key`) are type-checked against the English JSON.

## Scripts (client)

| Script | What |
|---|---|
| `npm run i18n` | Extract the keys used in the code into the JSON files (new keys appear empty in every language) and regenerate the types |
| `npm run i18n:status` | Show the translation progress per language – missing translations are a **warning**, never an error |
| `npm run i18n:watch` | `i18n` on every change (during development) |

`npm run build` runs `i18n` and `i18n:status` first; CI shows the status
too. A missing or empty translation shows the English text.

**Adding a text:** use `i18next.t("namespace:newKey")` in the code, run `npm run i18n`, fill in the English
text and the translations in the JSON files.

**Adding a language:** add it to `LANGUAGES` / `LANGUAGE_NAMES` in `languages.ts`, run `npm run i18n` (creates
the files with empty texts), translate.

## The reader's language

- The language detector keeps it in localStorage (`osct-language`) – the reader's choice, or on the first
  visit the device's language (first supported one of `navigator.languages`, else English).
- It is not part of the progress: progress is per book and "Reset book" deletes it; the language belongs
  to the reader across books and stays. Later it maps to the account settings of the API.
- Changed in Info → Settings → Language (`i18next.changeLanguage`); the app reloads and stays on the same
  view (the URL keeps it).

**Not translated (yet):** the book content – titles, entry texts, onboarding step texts, book info – comes
from `content/` as it is.
